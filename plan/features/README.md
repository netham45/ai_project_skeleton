# Feature Plans

Use feature plans for larger capabilities that span multiple task plans, systems, or proving layers.

Once the repository has real `PFxx` product features, add one rigid feature-definition file per feature here.

At minimum, each feature-definition file should declare:

- feature ID and name
- source vision references
- governing flow IDs
- governed docs, notes, checklists, logs, and tests
- required versus reviewed-no-change documentation surfaces
- bounded proof commands
- E2E asset and required E2E command
- E2E proof status fields
- key files used for milestone-gate drift warnings
- the per-feature snapshot baseline path
