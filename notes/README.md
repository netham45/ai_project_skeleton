# Notes

This folder holds the design, governance, inventory, traceability, and development-log artifacts that define how a project cloned from this skeleton is supposed to operate.

In this released skeleton, notes are part of the implementation surface from day one. They are not optional background docs and they are not meant to be filled in later only after code exists.

Use this tree to:

- declare the project mission and lifecycle stage
- record architecture and authority boundaries
- capture stack decisions explicitly
- track inventories, flow relevance, and traceability
- record development work through required logs
- keep documentation aligned with implementation and proof claims

The skeleton intentionally leaves project-specific stack and runtime details open. Those decisions should be written here during genesis and architecture by the real cloned project.
