# Documentation

This tree holds the user-facing and operator-facing documentation surfaces for a project cloned from this skeleton.

Use `docs/` for:

- setup and onboarding guides
- usage guides
- operator guides used in real runtime operation
- reference material for commands, configuration, and interfaces
- runbooks and troubleshooting material that real users or operators are expected to follow

Do not use `docs/` for governance, planning, traceability, or lifecycle control.
Those belong in `notes/`.

At minimum, cloned projects should decide:

- which documentation audiences exist
- which subtrees are authoritative
- which commands and examples must stay synchronized with the real product
- which features and flows require documentation updates before they can be claimed complete
